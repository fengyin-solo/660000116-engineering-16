# solo-6600001 - 在线协作白板应用

## 项目简介
构建一个在线协作白板应用，支持多人实时绘图、便签、形状工具，具备画布缩放/平移、图层管理、实时光标显示、导出为PNG/PDF功能，使用WebSocket实现多人同步

## 技术栈
- **前端**: React + TypeScript + Canvas API + Zustand
- **后端**: Node.js + Express + Socket.io
- **数据库**: 本地文件存储（`server/data/boards.json`，无需 MongoDB）

## 快速开始（推荐：一条命令统一启动）

在仓库根目录执行：

```bash
npm run dev
```

脚本会依次完成 **环境检查 → 端口/旧进程检查 → 依赖准备（缺失才安装）→
启动后端 → 启动前端 → 前后端连通与模板数据检查**，全部通过后输出访问入口：

- 画板访问入口：http://localhost:5173
- 后端健康检查：http://localhost:3001/api/health
- 模板数据（会议纪要 / 流程梳理 / 周计划）：http://localhost:3001/api/templates

前台运行时按 `Ctrl-C` 会同时停止前后端；数据文件不会被删除。

### 统一命令一览

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 检查并启动前后端（前台，合并输出两端日志，Ctrl-C 一并停止） |
| `npm run dev:bg` | 同上，但后台运行（关闭终端不影响服务） |
| `npm run dev:status` | 查看两端进程/健康状态与前后端代理链路（全部健康退出码为 0） |
| `npm run dev:logs` | 跟踪两端日志（`npm run dev:logs server` 只看后端） |
| `npm run dev:stop` | 停止由脚本启动的前后端进程 |
| `npm run dev:restart` | 重启前后端 |

可选参数（直接调用脚本时使用）：

- `--install`：强制重新执行两端 `npm install`（默认依赖已就绪时跳过，不重复安装）
- `--force`：端口被其他进程占用时，强制结束占用者后再启动（默认会报出占用进程 PID 与命令）

### 失败时会发生什么

任一环节失败都会：

1. 明确标出失败环节（如 `[依赖准备]`、`[后端启动]`、`[前端启动]`、`[前后端连通检查]`）和具体原因；
2. 打印相关日志末尾，便于区分是依赖缺失、服务未就绪还是页面到后端的连接问题；
3. 自动回收本次已启动的进程，避免残留；
4. 修复后直接重跑 `npm run dev` 即可，脚本会识别并清理上次的托管进程，已存在的 `server/data` 数据保持不变。

日志与 pid 文件统一放在 `.dev/`（已被 git 忽略）。

## 手工分别启动（仍然支持）

### 服务端
```bash
cd server
npm install
npm run dev
```

### 客户端
```bash
cd client
npm install
npm run dev
```

> 注意：手工启动的进程不由统一脚本管理。若端口被手工进程占用，`npm run dev`
> 会报出占用进程信息；确认可以结束后，可加 `--force` 让脚本处理，或先手动停止。

## 功能特性
- 多人实时协作绘图
- 画笔、矩形、圆形、直线、文本工具
- 便签功能
- 图层管理（新建、可见性、锁定）
- 实时光标显示
- 画布缩放/平移
- WebSocket实时同步
